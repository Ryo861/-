# 介護実習記録チェッカー（フェーズA）

Windows 11向けのフェーズAです。インストール不要のWindows版も用意します。PDFを表示し、教員が手動で付けた赤い番号とコメント、実習時間の計算結果を別PDFに保存します。AI・OCR・外部APIは使いません。初回の依存ライブラリ取得後はオフラインで使えます。

## Pythonインストール不要版

[Releases](https://github.com/Ryo861/-/releases) にある **practice-record-checker-windows-portable.zip** を使います。ソースコード用の「Code → Download ZIP」とは別です。ZIPをすべて展開し、`PracticeRecordChecker/PracticeRecordChecker.exe` をダブルクリックします。Pythonの導入や管理者としての実行は不要な設計です。`_internal` も必要なのでEXEだけを移動しないでください。学校のアプリ実行制限がある場合は管理者の許可が必要です。

[インストール不要版の使い方](docs/インストール不要版の使い方.txt) に手順とPCへの影響を記載しています。Windows CIの全テストと、作成したEXEによるGUI・PDF保存チェックが通ったものだけをReleaseにアップロードします。作成中はReleaseにZIPはありません。

以下はソースコードから起動する場合の手順です。

**まず [日本語の操作手順](docs/操作方法.md) を読んでください。** Pythonをまだ入れていない場合の手順もあります。

## できること

- ファイル選択によるPDFの複数投入、原本表示、ページ移動、拡大・縮小。
- 教員の手入力による時間計算。複数の休憩、明示した「休憩なし」に対応。休憩が空白なら要確認。日跨ぎは未対応で要確認。
- 画像をクリックして赤い丸番号の位置指定。コメントの追加・編集・削除・個別承認・位置調整。
- 位置不明なら、原本に番号を置かず「欄／位置不明・要確認」として末尾コメント一覧に表示。
- 承認済みコメントだけを別PDFに保存。長いコメントは一覧ページを増やして保持。
- 匿名IDを初期値として出力命名。氏名の自動推定なし。元の入力名は変更しない。
- 原本の全ページを順序どおり保持し、コメントがあれば末尾にページを追加。コメント・時間結果なしなら元のページ数のまま出力。
- 同一生徒と教員が確認した複数ページPDFを扱う。別生徒のページの自動分割はしない。
- 個別PDFの一括保存と、失敗した文書の個別再実行。同名出力の一括上書きなし。
- 保存済PDFの再表示。暗号化・破損・ページなしのPDFは読込対象外。

原本ファイルを消したり書き換えたりしません。原本と同じパス／同じファイルへの出力を拒否し、読込後の原本変更も検出します。PDFをラスタ画像だけに作り直さず、元のPDFページに番号を重ねる設計です。ただし出力PDFは再構築されるため、バイト単位で原本と同一になるものではありません。

## 初回起動（Windows）

1. Python公式の [Python 3.11.9 Windows 64bitインストーラー](https://www.python.org/downloads/release/python-3119/) をインストールします。学校管理端末では管理者に依頼してください。Python Launcherとtcl/tkを含めてください。
2. 配布ZIPを展開します。ZIPの中から直接実行しないでください。
3. `setup_windows.bat` をダブルクリックします。これは初回だけインターネットに接続し、必要なライブラリを入れます。
4. 「準備完了」と出たら `start_windows.bat` をダブルクリックします。
5. 「練習用PDFを作成」から空の練習フォルダーを選び、合成データで試してください。

GPUやモデルのダウンロードは不要です。Python 3.11系64bitをWindowsの想定環境とし、このクラウドではPython 3.13.5・Tk 8.6で画面を含めて検証しました。ソースコードからの起動はPythonが必要です。ReleaseのEXE版にはPythonが同梱されます。

## 開発者向け

リポジトリ直下で実行します。

```sh
python -m venv .venv
# Windowsは .venv\Scripts\python.exe を使います。
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m tools.sample_run --output outputs/demo
```

Linuxでディスプレイがない場合だけ、`bash tools/setup_headless.sh` → `bash tools/test_headless.sh` を使います。このクラウドでは `bash tools/setup_cloud.sh` で、システムPython/Tk 8.6を使う `.venv-gui` を準備します。画面起動は `.venv-gui/bin/python app.py` です。プラットフォーム標準Tk 9.0は日本語フォント非対応のビルドだったためGUIには使いません。仮想ディスプレイ準備はDebian 13向けで、Windowsには不要です。Tkinter自体はPythonのOSパッケージ／インストーラー側に必要です。

生成されたPDFはGit管理しません。`tools.create_sample`で実データのない練習用PDFを再生成できます（既存練習ファイルは上書きしません）。添削済みサンプルも配布ZIP内の `sample_data/添削済み見本` に含めます。

## 構成と技術選定

- `app.py` / `gui/`：標準Tkinter/ttkの日本語画面。追加のGUIフレームワーク不要。
- `core/models.py`：文書、手動候補、時間結果。認識モデルから独立。
- `core/time_checker.py`：決定論的時間計算。AIなし。
- `core/pdf_io.py`：pypdfで原本ページ保持、pypdfium2/PDFiumで表示、ReportLabで赤番号と日本語コメント生成。
- `core/batch.py`：順番に個別出力。一件の失敗で他の文書を失わない。
- `assets/fonts/`：BIZ UDゴシックを埋め込み、日本語コメントの文字化けを避ける。
- `tests/`：時間・ページ保存・座標変換・日本語フォント・原本保護・オフライン処理・GUIの受け入れテスト。
- `tools/diagnose.py`：OS、Python、CPUコア数、空き容量、WindowsのRAMのみ表示。記録本文や環境変数は表示しない。

PyMuPDFを採用せず、依存ライブラリとフォントの許諾情報を [LICENSES_AND_MODELS.md](LICENSES_AND_MODELS.md) に整理しました。商用配布前にはWindows版PDFiumに含まれる第三者ライセンスを別途確認してください。

## 検証と限界

実行結果は [フェーズA検証記録](docs/検証結果.md)、Windowsでの確認表は [受け入れ確認](docs/Windows受け入れ確認.md) を参照してください。Windows CIも用意しました。GitHubへのpushで実行されます。実行状況はリポジトリのActionsで確認してください。クラウドの検証結果とWindows CIの結果は別です。

未実装：手書きOCR、AI校正、傾き・明暗補正、ルール設定、赤い下線や自由線、ドラッグ＆ドロップ、単一PDFの生徒ごとの分割、ZIP一括出力、作業状態の再読込・履歴、ロイロノート自動返却。フェーズB/Cは今回の対象外です。コメント・時刻は終了するとメモリから失われ、再開可能な編集プロジェクトは保存しません。作成済みPDFと原本は残ります。

実際の未添削日誌は提供されていません。合成PDFで確認した結果を、実際の手書き認識精度の証明として使いません。Windows 11/10実機、16GB RAMでの検証は未実施です。30件処理の性能保証もありません。一括出力は1件ずつで、保存中は画面操作が一時的に止まる場合があります。

特殊なPDF（電子署名、PDF/A維持、入力フォーム、添付ファイル、特殊なページ箱、不正構造）の機能保持は保証対象外です。一般的な画像中心の実習日誌PDFを対象とし、すべての保存結果を教員が確認してください。大量の番号を同じ位置に置くと重なるため、位置を調整するか位置不明コメントにしてください。

個人情報を含むPDFやスクリーンショットはGitHubへ追加しないでください。原本・出力・ローカルの一時ファイルは学校が管理する保存先で扱ってください。処理はネットワークを使わず、全文ログやテレメトリーもありません。出力用一時PDFは保存成功・失敗時に削除しますが、強制終了時は保存フォルダーに `.checker-*.pdf` が残る可能性があります。アプリを終了した後、不要であることを確認して削除してください。
